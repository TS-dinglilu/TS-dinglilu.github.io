## 推送卡死的根因与解决（重要）

- **根因**：本机 git 凭据助手（`credential.helper=helper-selector` → 约 100s 后转 `git-credential-manager.exe`）在非交互/无头场景**挂起不返回**。表现：`git push` 几分钟无任何输出，`timeout` 杀掉父进程后子进程仍持有管道，导致 Python `subprocess.run(timeout=...)` 也跟着挂。`git ls-remote`（不需要凭据）却秒回，容易误判为纯网络问题。
- **验证**：`GIT_TRACE=1` 显示卡在 `git credential-helper-selector get`；非交互参数 `GCM_INTERACTIVE=never` 无效。
- **解决方案（已落地）**：
  1. `scripts/export_git_cred.ps1`：用 CredRead P/Invoke 从 Windows 凭据管理器读出 `git:https://github.com` 凭据（用户 TS-dinglilu，40 位 token），写入临时文件并输出路径；调用方用 `git -c credential.helper= -c "credential.helper=store --file=<path>"` 推送，用完即删。实测 **14 秒完成**。
  2. `publish_all.py::push_with_retry` 改为**优先走凭据直连通道**，常规 `git push` 仅兜底。
- **踩过的三个坑（写脚本时注意）**：
  - `-File` 传含中文的脚本路径会解析失败 → Python 侧先把脚本复制到 ASCII 临时目录；
  - 脚本含中文但无 BOM 时，PowerShell 5.1 按 GBK 解析报 ParserError → 复制时用 `utf-8-sig` 落盘；
  - `$Host` 是 PowerShell 保留变量，不能作 param 名（VariableNotWritable）→ 改 `$CredHost`；
  - Python 传 `store --file=C:\...` 反斜杠会被 git config 当转义符 → 必须换成正斜杠。
