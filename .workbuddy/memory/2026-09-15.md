## 追加：兜底通道加固（同日）

提交 `7b321f4`（紧接 `7ba64a0`）。

### 起因
用「故意打坏的 PATH」测兜底脚本时暴露两个真问题：
1. 脚本里只做了**可执行文件定位**（`_tool()`），但 git/ssh 运行时还需要**自己目录在 PATH 上**；
   实测损坏 PATH 下 `git` 直接跑不起来 → `repo_slug()` 静默返回 `None`。
2. `repo_slug()` 返回 `None` 后代码**没有拦住**，继续拼出 `/repos/None/keys` 去请求，
   拿到 404 并报出**误导性的错误信息**（像是权限问题，其实是仓库地址没解析出来）。

### 修法
- 新增 `_child_env()`：把 PortableGit 的 `cmd` / `usr/bin` / `mingw64/bin` 与系统目录
  **前置到子进程 PATH**（再拼上原有 PATH）。git / ssh / ssh-keygen / 凭据导出脚本 的子进程统一用它。
- 所有外部命令调用点改为经 `_tool(name)` 解析（PATH 找不到就回退已知目录）。
- `ssh_fallback_push()` 与 `selftest()` 在 `repo_slug()` 失败时**立刻返回明确错误**，不再往下走。

### 验证
`env -i PATH=/c/Windows/System32 <python> scripts/ssh_fallback_push.py --selftest`
（故意打坏 PATH）全链路通过：仓库解析 → 凭据导出 → 密钥注册 → SSH 认证 → ls-remote 成功 → 撤销 204。
收尾复查：数据库/仓库现存部署密钥为空，无临时目录残留。

### 可复用的经验
**「定位到 exe」≠「能以损坏 PATH 运行」**。在本机这种 PATH 偶发损坏的环境里，
给子进程前置必要目录比只找 exe 路径更可靠，而且这类脚本要**在失败处立刻报错**，
不要带着 `None` 继续拼 URL 请求（会得到与真实原因无关的 404/401）。

### 本轮新增环境坑（重要）
1. **Bash 里不能用 `powershell.exe`**：被安全策略直接拒绝（"Invoking PowerShell from Bash bypasses PowerShell security checks"）。
   想手动导出 git 凭据时，改走 `publish_all.py --push`（Python 子进程里调 ps1 是允许的），或直接用 PowerShell 工具。
2. **别把 `publish_all.py --push` 的输出管到 `tail`**：管道缓冲导致进程被 SIGTERM 时**输出全丢且看不出进度**，
   表现为「静默失败」。正确姿势是重定向到文件（`> ../logs/push_YYYYMMDD.log 2>&1`）再用 Read/tail 看。
3. **Windows 生成的临时文件是 CRLF，会毁掉 shell 循环里的 curl**：用 Python `open(...,"w")` 写出的 URL 列表
   每行末尾带 `\r`，`while read` 读出来的 URL 尾部多一个回车 → curl 对每条都返回 `000`，
   极易被误判成"网络全断"。**读入前先 `tr -d '\r'`**（或 Python 侧用 `newline="\n"`）。
   教训：单条 curl 200、循环里全 000 时，先怀疑数据而不是网络。
